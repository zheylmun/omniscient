# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`omniscient` is a local MCP server (single Rust binary, edition 2024) that gives MCP clients **semantic, distilled** code search. It indexes a repo into a local LanceDB vector store and exposes three stdio tools — `search(query, k?)`, `read_file(path, focus?)`, and `diagnostics()` (an end-to-end self-test). `diagnostics` runs only on explicit call, never on the connect handshake, so the fast-handshake invariant is preserved. Embeddings are computed by an **external** local llama.cpp `/v1/embeddings` endpoint; there is no in-process inference.

## Commands

```bash
cargo build                 # debug build
cargo build --release       # -> target/release/omniscient
cargo test                  # full suite; no network/server needed (uses MockEmbedder)
cargo test chunk::          # run one module's tests (chunk|config|embed|index|freshness|distill|engine)
cargo test --test integration   # the end-to-end integration test
cargo test embed::live -- --ignored   # the ONE network test: needs a running llama.cpp embeddings server

cargo clippy --all-targets -- -D warnings   # the lint gate the pre-push hook enforces (clippy pedantic)

# Run the server / debug the index (require a reachable embeddings endpoint to build the Engine):
cargo run -- serve --repo <path>      # stdio MCP server
cargo run -- status --repo <path>     # embedder id + file/chunk counts
cargo run -- reindex --repo <path>    # delete .omniscient/ then rebuild
cargo run -- doctor --repo <path>     # the diagnostics report, exit 1 on FAIL
```

The whole suite runs offline because tests inject `embed::MockEmbedder` (deterministic, in `src/embed.rs`). Only the `#[ignore]`d `embed::live` test hits a real server.

**Every implementation task's verification must include `cargo clippy --all-targets -- -D warnings`, not just `cargo build`/`cargo test`.** The pre-push hook runs clippy at the `pedantic` level (`[lints.clippy]` in `Cargo.toml`) promoted to errors — code that builds and tests green can still be rejected at push time. Fix lints idiomatically (this codebase uses **no** inline `#[allow(clippy::…)]`); prefer splitting an over-long fn into helpers over silencing `too_many_lines`. When writing plans, add the clippy step to each task's verification alongside the test run.

## Architecture

The pipeline is a one-directional chain, wired only inside `src/engine.rs` (`Engine`):

```
freshness::scan  →  chunk::chunk_file  →  embed::Embedder  →  index (LanceDB)  →  distill::distill_context
```

- **`engine`** — the only module that composes the others. `Engine::search` is the single entry point used by both the MCP tools and the CLI.
- **`freshness`** — walks the repo (gitignore-aware) and blake3-hashes files; `diff` against stored hashes yields changed/deleted.
- **`chunk`** — tree-sitter for Rust/Python/TypeScript (one chunk per top-level definition), line-window fallback for everything else. `chunk_file` is purely *structural* and applies no size budget; `split_for_embedding` is a separate function called only on the indexing path.
- **`budget`** — `ChunkBudget`: the adaptive per-chunk byte budget. Starts optimistic from the probed context window and is corrected by the endpoint's own overflow reports. Shared across a reconcile.
- **`caps`** — parses `GET /props` (model-scoped and plain) and `GET /v1/models` into `ServerCaps`, accumulated across probes with `ServerCaps::or` (`max_input_tokens`, `total_slots`, and a `CapsSource` recording which probe answered). Failure-soft: a non-llama.cpp endpoint yields empty caps, never an error.
- **`embed`** — `Embedder` trait. Real impl is `LlamaCppEmbedder` (HTTP); `MockEmbedder` is the test seam. `build_embedder` is `async` (at connect time it probes the embedding dimension and the server's capabilities). `Error` classifies embed failures: `EmbedAuth` (fatal for the run), `EmbedTransient`/`Timeout` (retryable), `EmbedContextExceeded` (a budget measurement, not a failure).
- **`index`** — LanceDB table + a `meta.json` sidecar recording the embedder id and dim.
- **`distill`** — deterministic, NO LLM: merges overlapping hits, strips noise, trims to a token budget.
- **`watcher`** — optional background filesystem watcher (`notify-debouncer-full`); debounced FS events outside `.omniscient/` mark the index dirty and wake an async reconcile task. A `WatchGuard` keeps the OS watcher alive and aborts the task on drop.
- **`refresh`** — `RefreshState`: the `dirty`/`watch_active` atomics + reconcile mutex shared by the watcher and `Engine`. `can_skip_scan()` (watcher active AND not dirty) is the gate that lets `search` skip its scan.
- **`mcp`** — rmcp stdio server. **`cli`** — clap (`serve`/`status`/`reindex`).

### Invariants you must not break

- **Always-fresh (watcher-aware):** `Engine::search` calls `ensure_fresh()` before querying. It may skip the filesystem scan *only* when a healthy watcher guarantees the index already reflects the working tree (`RefreshState::can_skip_scan()`); in every other case — watching disabled, watcher not yet started, embedder was down, a watch error — it falls back to a full `reconcile()`. Never add a search path that can return stale results when the watcher is not known-caught-up.
- **Nothing tree-sized blocks the connect handshake:** `serve` must reach `server.serve(stdio())` fast, so the watcher is set up on a background `spawn_blocking` task (`mcp::spawn_watcher_deferred`), never inline. `notify`'s recursive `.watch()` builds its file-id map by walking the whole tree — gitignore-blind, so it descends into `target/`, `node_modules/`, `.git/` — which on a large repo outlasts an MCP client's connect timeout. This is safe precisely because of the always-fresh invariant above: until deferred setup finishes and a first reconcile flips `watch_active`, `can_skip_scan()` is false and `search` scans, so late watcher activation never serves stale results. Keep engine init lazy (below) and watcher setup deferred — don't move either onto the handshake path.
- **Embedder id keys the index:** `index/meta.json` stores the embedder id + dim. On mismatch (e.g. config `model` changed) `Index::open` drops the table and forces a full rebuild. The index lives in `<repo_root>/.omniscient/` (excluded from the scan because dotfiles are skipped).
- **`[embedder] model` must be an id the endpoint actually serves, and the defaults are wired so it is.** A bare `llama-server` ignores the `model` field, but `llama serve` is a *router*: it registers a `-hf`-loaded model under the repo id and answers any other id with `400 model '<id>' not found` — on `/v1/embeddings` and on the `/props?model=` probe alike. So `model` defaulting to a friendly nickname while `hf_repo` named a real GGUF made the shipped configuration fail against the documented setup on the very first connect probe. Two things keep them together now, and both matter: `model` and `hf_repo` **default to the same string** (`config::DEFAULT_MODEL`, asserted by a test), and `auto_start` passes **`--alias <model>`** so a spawned server registers under the id we are going to ask for whatever `hf_repo` says. Without the alias, a user who changes only one of the two gets a server that cannot answer, and because that 400 never resolves by waiting, `connect_managed`'s readiness poll would burn the whole `auto_start_timeout_secs` (600 s by default) before reporting it. `connect_managed` additionally aborts immediately on `EmbedAuth` — the one error that provably never resolves by waiting — and logs the underlying error with each "still waiting" line so a doomed wait explains itself. Other non-retryable errors are still polled, because a 400 from the router *can* be a startup race: the model is registered only once its GGUF is fetched and loaded.
- **The default model is chosen for reach, not for peak quality.** `DEFAULT_MODEL` is Qwen3-Embedding-**0.6B** at Q8_0 (~640 MB), which runs on CPU or an integrated GPU, so `omniscient` works out of the box on an ordinary developer machine. Scaling up to 4B/8B is a two-line config change (`model` *and* `hf_repo`, same family so `pooling = "last"` still holds) and is documented as such in README and `omniscient.example.toml`. Don't "upgrade" the default to a model that needs a large discrete GPU — the whole point is that the out-of-the-box path works before anyone reads the tuning docs.
- **No LLM in `search`:** distillation is deterministic. v1 deliberately has NO generative "answer" mode, NO in-process/candle embeddings, and NO device (Metal/CUDA) policy. The `Embedder` trait is the seam for adding in-process embeddings later — keep that boundary clean rather than reintroducing those features inline.
- **stdout is reserved for the MCP protocol.** All logging goes to stderr (`tracing_subscriber` writer is stderr). Never `println!` in the `serve` path; `status`/`reindex` print to stdout only because they are human CLI commands.
- **No chunk may exceed the endpoint's context window — and this is a guarantee, not an estimate.** A single oversized input is rejected with HTTP 400 `exceed_context_size_error`, and because a failed file's hash is never stored, a chunk that can never be split small enough would fail *every* subsequent reconcile — wedging `search` permanently. The old defence was a deliberately pessimistic bytes-per-token guess; the current one is a measurement loop with a termination proof.
  - **Start optimistic.** `ChunkBudget::from_probe` seeds the budget from the endpoint's reported window (`/props?model=`, then plain `/props`, then `/v1/models`) at `OPTIMISTIC_BYTES_PER_TOKEN` (4). A reported `0` — what a `llama serve` supervisor answers about itself — counts as unknown, and `[embedder] max_chunk_tokens` seeds it instead. Over-estimating costs a few rejected requests once and self-heals; under-estimating splits large-but-legal definitions forever and degrades every query.
  - **Every overflow is a measurement, not a guess.** The 400 carries `n_prompt_tokens` for a payload whose byte length we know, which is an exact bytes-per-token ratio for real content. `ChunkBudget::tighten` folds it back in (15/16 headroom, which only has to cover request framing now that the ratio is measured). **`sent_bytes` must be the rejected chunk's real byte length, not the budget it was split against** — `Engine::chunks_for_embedding` returns that length alongside the pieces. The budget is only an upper bound, and passing it inflates the measured ratio whenever a chunk lands well under it (the common case), so each round shrinks the budget by little more than the headroom factor and a perfectly splittable file can exhaust the round bound before converging. The budget is *shared across the whole reconcile*, so one file's correction applies to every later file — file B never repeats file A's rejected round-trip.
  - **It provably converges and terminates.** Tightening is monotonic (`compare_exchange` never raises the budget, so a laxer later report cannot undo an earlier correction) and strictly decreasing on every overflow (`n_prompt_tokens > n_ctx` is what caused the rejection, so the recomputed target always lands below the budget that produced it). It floors at `n_ctx` **bytes** less `SPECIAL_TOKEN_SLACK` (4) — 1 byte per token, minus room for the BOS/EOS the server adds — which always fits whatever the content, CJK or base64 or minified JS, because a token is never smaller than a byte. The slack matters: without it a chunk of exactly `n_ctx` bytes of 1-token-per-byte content tokenizes to `n_ctx + 2`, is rejected while already at the floor, and fails every reconcile forever — keeping `dirty` set and defeating `can_skip_scan()` permanently. The per-file retry loop is `Engine::embed_file_with_overflow_retry` (bounded at 8 rounds as a backstop only — the real terminator is that each round's budget is strictly below the previous round's). **Being at the floor is a property of the budget's state, not of `tighten`'s return value.** `Tightened::Unchanged` means only "no smaller target than what is already there", which a *concurrent* file's correction also produces; treating that as the floor would fail a perfectly embeddable file with a false "even at the minimum chunk size" error. So on `Unchanged` the loop retries whenever the current budget is below what this attempt used (someone else's correction is tighter — use it), reports the floor error only when the failing attempt was itself made at or below `n_ctx` bytes, and reports a distinct "does not reduce the budget" error for a server whose numbers are self-inconsistent (which is what keeps every continuing round strictly decreasing).
  - **The split itself always advances.** `enforce_byte_budget` covers all three ways a chunk gets too big: an oversized tree-sitter definition (emitted whole, never recursed into), an oversized line window, and a single oversized line — minified/generated files have no newline to split on, so only a UTF-8 char-boundary split handles them, and when the budget is narrower than one character it emits that whole character rather than spinning or slicing mid-codepoint. Concatenating the pieces reproduces the input exactly.
  - **Splitting lives on the embedding path only — and `read_file`'s focus branch *is* an embedding path.** `chunk::chunk_file`/`chunk_source` are structural and budget-free; `chunk::split_for_embedding` is applied wherever chunks are handed to the embedder: `Engine::chunks_for_embedding` (indexing) and `read_file`'s `Some(focus)` branch (`Engine::focus_entries`), which embeds every chunk to rank it. **The focus *query* is embedded once, outside the re-split loop, and its overflows are NOT fed to the budget:** it is caller-supplied and never split, so its token count measures nothing about chunk size, and `tighten`'s monotonicity would make one oversized `focus` argument ratchet the shared budget to its floor permanently — for every file indexed afterwards, with the undersized chunks persisted and no `CHUNKER_VERSION` bump to undo them. **Both paths also feed overflows back into the shared budget** via `Engine::next_budget_after_overflow` — the one place the floor test lives. A focus read that swallowed its rejection instead would fail the tool call *and* teach the budget nothing, so the identical next call would fail identically; on a cold index, where the budget is still at its optimistic start, that is the likely case rather than the exotic one. The focus loop's re-splits sit inside a single `search_timeout_secs` deadline, so recovery cannot multiply the caller's timeout by the round count. `read_file` is deliberately not exclude-filtered, so a minified 900 KB one-line bundle is exactly what a focus read gets pointed at; unsplit it would be a 400 and a failed tool call. The **outline** branch stays structural — showing whole definitions is its contract, and splitting there is what once turned one big function into entries whose "signature" was a body fragment. A focus entry that is a piece of a split chunk says so in `why_matched` ("partial"). Reconcile chunks **lazily, per file, at embed time** — reading `self.budget.bytes()` at the moment that file is chunked — rather than against one snapshot taken before any embedding, so a correction made moments earlier by a concurrently-embedding file is already in force.
  - Splitting changes chunk *content*, so it is gated by `CHUNKER_VERSION` (now **6**).
- **All per-language knowledge lives in `chunk::LANGUAGES`, one `LanguageSpec` entry per language.** Extension mapping, grammar, def kinds, the optional `symbol_for`/`is_test_item` hooks, and the language's test-file globs are all fields of that one entry; `LanguageSpec` deliberately has no `Default` impl, so adding a language forces every field to be considered explicitly. The whitelist (`config::is_language_allowed`) matches name, *family*, or extension — `family` is what lets `languages = ["typescript"]` admit `.tsx` (its grammar name is "tsx"); the default whitelist is **empty = index everything**, with non-grammar files falling back to line windows. Two things are not compiler-enforceable and are guarded by tests instead: `registry_changes_require_a_chunker_version_bump` (a blake3 fingerprint of the registry's observable surface, `REGISTRY_FINGERPRINT`, recorded next to `CHUNKER_VERSION` — the failing assertion prints the new value) and `registry_test_globs_flow_into_resolved_excludes` (per-language test globs must reach `freshness::resolve_excludes`). Don't add language matches/dispatch outside the registry — three parallel `match` statements is exactly what it replaced.
- **One bad file must never block the index.** `reconcile_inner` collects per-file results rather than propagating the first embed error, and the failure *class* decides the policy:
  - **Overflow is a budget signal, not a failure.** `EmbedContextExceeded` tightens the shared budget and re-splits that file; only a rejection at the 1 byte/token floor becomes a real error.
  - **Transient failures are retried, not skipped.** `EmbedTransient`/`Timeout` (`Error::is_retryable`) go through a bounded retry ladder with backoff (`embed_with_retry`, 100 ms then 400 ms) re-sending the *same* chunks — a blip must not cost a file its place in the index, but a persistently failing endpoint must not be hammered either.
  - **Auth failure aborts the whole run.** `EmbedAuth` (`Error::is_fatal_for_run`) dooms every remaining file, so `reconcile_inner` returns immediately rather than repeating the same rejection once per file.
  - **…but enough consecutive transient failures abort it too.** Per-file isolation is the right response to a bad file and to a blip; it is the wrong response to a dead endpoint. A refused connection classifies as `EmbedTransient` — correctly, since a single request cannot distinguish an outage from a blip — and `EmbedTransient` is not `is_fatal_for_run`, so without a circuit breaker every changed file rediscovers the same dead endpoint through the full ladder (3 attempts + 500 ms of backoff). Because `ensure_fresh()` deliberately sits **outside** `search_timeout_secs`, a branch switch that changes thousands of files then turns one `search` into a multi-minute stall. `reconcile_inner` therefore counts consecutive retryable failures and gives up at `CONSECUTIVE_TRANSIENT_LIMIT` (5), returning an `EmbedTransient` that names the endpoint rather than a file. Any success resets the counter, and a non-retryable failure does too — that one says nothing about the endpoint. The threshold must stay comfortably above 1: each failure counted has already exhausted three attempts of its own, so tripping on a single unlucky file would defeat the per-file isolation this sits on top of.
  - **Anything else is scoped to one file.** It logs a warning and is recorded in `ReconcileSummary::failed`; its hash stays unwritten, so `diff` offers it again next pass. Index write errors remain fatal — they mean the store is unhealthy, not that one file is unembeddable.
  - **A file that yields no chunks still gets its hash recorded.** `Index::upsert_file` takes `file_hash` explicitly (not off `chunks[0]`) precisely so the empty case can write a `file_meta` row after dropping the file's chunk rows. Without it an empty or whitespace-only file is absent from `file_meta`, so `diff` reports it as changed on *every* reconcile forever and repeats the delete on every search that reconciles.
- **An aborted run is recorded too.** `reconcile_guarded` stores a `ReconcileSummary` on the error path as well as the success path (one entry keyed `ABORTED_RUN`), so `diagnostics` cannot report "no failures" straight after a run in which a rejected API key doomed every file.
- **Skipped is not failed.** A path that will not read back as UTF-8 is dropped silently, never recorded in `failed`: it is not a broken file, just not one we index, and counting it would make `refresh()` — and so `reindex`/`status` — exit non-zero on any repo containing a binary. Each changed file is read exactly **once**, inside the bounded `buffer_unordered` stage, so only `concurrency` file contents are ever live (O(concurrency) memory, not O(repo)) and a file's overflow re-splits reuse the source already in hand rather than re-reading it per round.
  - **The two callers differ deliberately.** `reconcile()` (the `search` path) tolerates failures — a partial index beats a broken tool call — while `refresh()` (used by `reindex`/`status`/tests) returns an error naming every failed file, so those commands exit non-zero instead of printing success over a rebuild that did not happen.
  - **`dirty` stays set whenever anything failed.** `DirtyGuard` is only disarmed on a wholly clean pass (`ReconcileSummary::is_clean`), and it also re-marks on cancellation or an early return. Otherwise a wholly-down embedder would leave the state clean+active and let `search` skip the scan over an empty index, breaking always-fresh. `diagnostics` surfaces the same failures via `Engine::last_failures`.
- **Vectors are L2-normalized** (by `embed`), so cosine distance == dot product. `read_file`'s focus ranking relies on this.
- **`arrow-array`/`arrow-schema` are pinned to `58` to match `lancedb` 0.30**, which does not re-export arrow. Do not bump them independently or add a second arrow version — verify with `cargo tree | grep arrow-array` (must be a single line). `reqwest` is rustls-only (`default-features = false`); don't let a dep pull OpenSSL back in.

### rmcp specifics

`src/mcp.rs` implements `ServerHandler` **manually** (routing through `ToolRouter::call`/`list_all`) rather than via `#[tool_handler]`, because the macro's generated code collides with this crate's `Result` alias. The `Engine` is initialized **lazily** on first tool call via `tokio::sync::OnceCell::get_or_try_init` — so `serve` starts and `tools/list` works even when the embeddings endpoint is down, and a failed init is retryable (not poisoned).

## Configuration

`omniscient.toml` at the repo root (see `omniscient.example.toml`): `[embedder] base_url/model/api_key` (+ `auto_start/llama_bin/hf_repo/pooling/auto_start_timeout_secs`, `max_batch_chunks/max_batch_bytes`, `max_chunk_tokens`, `embed_concurrency`, `request_timeout_secs`), `[search] relevance_ratio/max_results/token_budget/search_timeout_secs`, `[watch] enabled/debounce_ms`, `languages`, `strip_comments`, `index_tests`, `exclude`. Defaults apply if the file is absent. Two of these knobs are *overrides of an auto-detected value* and are best left unset:

- **`max_chunk_tokens`** (default 2048) seeds the chunk budget only when the endpoint reports no context window at all. A probed window always wins, and any overflow the endpoint reports corrects the budget regardless of where it started. It therefore matters only for an endpoint that reports neither its window *nor* a structured `exceed_context_size_error` — there is nothing to measure there, so the configured number is all there is.
- **`embed_concurrency`** (unset by default) overrides the concurrency derived from the server's reported `total_slots` (`/props`, which only reports it when the probe is **model-scoped** behind a router), clamped to at most 8. An endpoint that reports no slot count falls back to serial (1). See `engine::resolve_concurrency`.

**Auto-start (opt-in, off by default):** when `[embedder] auto_start = true` and `base_url` is unreachable, `build_embedder` spawns a local llama.cpp server (`llama serve -hf <hf_repo> --port <port> --embedding --pooling <pooling> --ctx-size N --batch-size N --ubatch-size N`, port parsed from `base_url`) via `embed::ManagedServer`, polls the endpoint until ready (or `auto_start_timeout_secs`), and ties the child's lifetime to the embedder (`kill_on_drop`). **`N` = `server_ctx_size` = `max(2048, max_batch_bytes)`, and this sizing is over-conservative on purpose — it is not load-bearing.** A token is always ≥ 1 byte, so `max_batch_bytes` is a safe ceiling on any single request, and sizing off the same knob that bounds our batches means they can't drift. Do not re-derive a stricter justification for it: two claims that once appeared here were measured false against `llama serve` build `b9821` (both 4B and 8B): a pooled embedding sequence does *not* have to fit whole in one ubatch (a 6001-token input succeeded against `n_ubatch = 4096`; llama.cpp splits the sequence across ubatches), and batch *totals* are not bounded by `n_ctx` (20 inputs totalling 60020 tokens succeeded on a server reporting `n_ctx: 40960`). Only **per-item** size is enforced — which is what `enforce_byte_budget` bounds. So `max_batch_bytes`-derived sizing costs KV memory on a spawned server but cannot cause the "starts fine, dies mid-use" failure; right-sizing it is a perf change, not a correctness one. The documented manual `llama serve` command must carry these flags too. An already-reachable endpoint is always reused and never spawned over — and if `connect()` fails while something is still listening on the port (a TCP probe, `endpoint_listening`, confirms it), the real error is surfaced rather than spawning a second server that would collide on the port. The child's stdout is sent to `/dev/null` (stdout is reserved for MCP); its stderr is inherited so download/load progress shows. Only a **local** host (`localhost`/`127.0.0.1`/`::1`, not the `0.0.0.0` bind wildcard) is spawnable; a remote `base_url` errors.

**Chunk context budget (adaptive):** at connect time `LlamaCppEmbedder` probes, in order, `GET /props?model=<id>`, plain `GET /props`, then `GET /v1/models` for the endpoint's real per-input token limit (`Embedder::max_input_tokens`, parsed in `caps`). **The `model` query parameter is what makes the first probe work behind a `llama serve` supervisor:** unscoped, the router answers about *itself* (`{"role":"router", ..., "n_ctx": 0}`, no `total_slots` at all); scoped, it proxies through to the backend and returns the real `n_ctx` and `total_slots` together. Measured against build `b9821`: `/props` unscoped gave `n_ctx: 0`, `/props?model=Qwen/Qwen3-Embedding-8B-GGUF:Q8_0` gave `n_ctx: 40960, total_slots: 4`. The id is appended as a real query parameter (`embed::probe_url`), never interpolated, because llama.cpp ids contain `/` and `:` and must be percent-encoded. All three probes are best-effort — a non-llama.cpp OpenAI-compatible endpoint reports nothing — and their results are **accumulated with `ServerCaps::or`, not replaced**: only `/props` ever reports `total_slots`, while `/v1/models` is sometimes the only source of a window, so overwriting one with the other silently loses a discovered slot count and drops embed concurrency to serial. Whatever the probe yields (or `[embedder] max_chunk_tokens` when it yields nothing) seeds `ChunkBudget` at `OPTIMISTIC_BYTES_PER_TOKEN` = 4 bytes/token, and from there **the budget corrects itself from the server's own rejections** — see the chunk-budget invariant above for the convergence argument.

**The self-correction runs in one direction only, so the probe still matters.** An overflow is the only signal there is, and it fires only when a chunk is too *big*. A seed that is too high costs a couple of rejected round-trips and then converges; a seed that is too low produces no overflows at all, so nothing ever corrects it and the under-split is permanent. Do not describe the budget as self-healing without that qualifier. This is why the scoped `/props` probe is worth three requests at connect time: on an endpoint that reports no window anywhere, `max_chunk_tokens` is not a starting point that gets refined, it is the value the budget keeps.

`diagnostics()` reports the probed window *and which probe answered it* (`from /props` / `from /v1/models` / `not reported — falling back to [embedder] max_chunk_tokens = N`), the effective byte budget and whether an overflow has tightened it, the derived embed concurrency and the slot count it came from, and any files the last reconcile failed on — so a misconfigured router is visible rather than inferred.

**Authenticated endpoints:** `[embedder] api_key` sets the bearer token sent as `Authorization: Bearer <key>` on every embeddings request — for a llama.cpp server started with `--api-key` or an OpenAI-compatible router. A whole-string `${VAR}`/`$VAR` value is expanded from the environment at connect time (via `EmbedderConfig::resolved_api_key`, which errors if the variable is unset), so the literal secret never has to live in the config file and is never persisted expanded; any other value is used literally. Diagnostics reports `embedder.api_key` as an override by **name only** — never its value.

**Result selection is relevance-shape, not fixed-k:** `distill_context` returns every entry scoring at least `relevance_ratio` (default 0.75) of the top entry's score, so result count follows the score distribution — a sharp query returns few, a broad one many. `max_results` (the index fetch ceiling, overridable by the MCP `k` arg) and `token_budget` are caps; the single best match is always returned (this also covers a non-positive top score, where the ratio floor would otherwise admit nothing).

**Repo resolution (`cli::resolve_repo`):** an explicit `--repo` is honored as given (only normalized to an absolute path via `canonicalize_repo`, no git-root walk); with no `--repo` the repo root is the `.git` ancestor of the launch cwd (`find_git_root`), and omniscient errors out rather than indexing a non-repo dir. This is what lets one user-scope `claude mcp add -s user omniscient omniscient -- serve` registration work across every repo. `./install.sh` (= `cargo install --path . --force`) puts the binary on PATH.

- **Dependency lock files are always excluded from indexing** by built-in globs (`Cargo.lock`, `package-lock.json`, `yarn.lock`, `pnpm-lock.yaml`, `poetry.lock`, `go.sum`, etc. — see `DEFAULT_EXCLUDES`). They are large, generated noise; `go.mod` is kept. Not gated by `index_tests`.
- **Test/fixture files are excluded from indexing** by built-in globs: the language-agnostic set in `freshness::DEFAULT_TEST_EXCLUDES` (`tests/`, `__tests__/`, `**/*_test.*`) plus each language's own conventions from `chunk::LANGUAGES` (`benches/` for Rust, `test_*.py`/`conftest.py` for Python, `*.test.*`/`*.spec.*` for JS/TS); `examples/` is kept. `index_tests = true` disables the test built-ins (not the lock-file ones); `exclude = [...]` adds more globs. Applied in `freshness::scan` via `ignore`'s `OverrideBuilder`. Exclusion changes need NO reindex — they shift file *membership*, which the always-fresh `diff` already reconciles (unlike `CHUNKER_VERSION`, which changes chunk *content*).
- **Exclusions are enforced at BOTH index time and read time.** Beyond `scan`, `Engine::search` filters hits through a `Gitignore` matcher (`freshness::exclude_matcher`) built from the same `resolve_excludes` list, so an excluded path never surfaces even during the index-lag window (embedder down, mid-reconcile, watcher not caught up) before `diff` purges it. Both paths are driven by one exclude list so they cannot diverge. `read_file` is NOT filtered — an explicit path read is honored.
